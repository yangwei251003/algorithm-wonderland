# 算法奇境 2.0 开源恢复说明

核对日期：2026-10-26。源码公开与成品验收是两件事：当前已生成 84 条影片、252 张漫画，84 条影片完成有界采样画面审查；**完整连续视听验收仍为 0/84**。自动解码和 ASR 不算亲耳听审。公开体验入口 [算法奇境 2.0](https://yangwei251003.github.io/algorithm-wonderland/) 已提供交互、漫画和文字稿，无需本地启动；高清影片仍由本地审查版提供。

## 先恢复可以运行的网页

源码仓库保留平台、算法、教学内容、测试、制作工具和依赖锁。漫画及较大的冻结教学 JSON 随同版本的必要素材 ZIP 提供，需从源码仓库的 Release 下载，解压到克隆目录根部，合并目录；不要多套一层文件夹。以实际 Release 附件及校验清单为准。

解压后至少检查：

- `public/media/catalog.json` 与 `public/media/<id>/comic-analogy.png`、`comic-rules.png`、`comic-summary.png`：网页漫画与目录。
- `media/exports/<id>.json` 及脚本引用的独立反例 JSON：真实教学记录；`<id>.film.json` 由后文的准备命令在本机生成。
- `media/scripts/<id>.json`、`media/comics/<id>/review.json`：影片脚本与原漫画审查记录。

这些教学 JSON 是普通原文件，**无需解冻或解密**。只克隆代码不会自动获得全部素材，更不会自动获得全部电影。网页交互在浏览器内真实计算；制作 JSON 用于恢复同一教学案例和影片，不是网页预录动画。

在仓库根目录，使用 Node.js 22.12 或更新的兼容版本：

```powershell
npm ci
npm run dev
```

打开终端显示的地址，默认 `http://127.0.0.1:5186/`。检查和静态构建命令：

```powershell
npm test
npm run build
npm run preview
```

`package-lock.json` 是安装依据。不要双击 `dist/index.html`，后台计算线程需要 HTTP/HTTPS 服务。影片未随源码素材提供时，目录不应保留指向缺失影片的播放链接；使用当前源码发布所附的目录文件。

## 恢复媒体制作环境

网页不需要 Python。重新制作 Manim 影片时才安装 Python 3.12 与 uv，然后在 PowerShell 运行：

```powershell
Push-Location media/manim
uv sync --frozen --python 3.12
Pop-Location
```

`media/manim/pyproject.toml` 和 `uv.lock` 锁定本制作环境：Manim **Community 0.22.0**，不是 ManimGL；当前锁含 edge-tts 7.3.1、imageio-ffmpeg 0.6.0、Pillow 12.3.0。Pillow 必须保持 `<13`，这是现有图片层的兼容要求。本机实测 Python 3.12.6，随 imageio-ffmpeg 使用的 Windows FFmpeg 为 7.1；其他平台二进制及系统图形依赖需重新验证。

中文绘图使用 `Microsoft YaHei`。非 Windows 环境需安装可用中文字体并调整字体配置，再检查缺字与排版。公式用 Text 与矢量排版；当前管线不要求或声称已经配置 LaTeX/MathTex。

Remotion 的 `remotion`、`@remotion/player`、`@remotion/cli` 均为 **4.0.538**，React 为 **19.2.0**，由根目录 `package-lock.json` 一并恢复。正式网页交互入口是 `src/components/InteractiveFilm.tsx`；`media/remotion` 是独立能力探针，不是 84 条正式影片。需要查看探针时：

```powershell
npx remotion studio media/remotion/studio.tsx --no-open --port 5191
```

## 从冻结输入重新制作一项

以 `bfs` 为例，在项目根执行。公开素材中的漫画与生产原图使用不同文件名；按角色逐一恢复，不能拿缩略图或草稿替代：

```powershell
$algorithmId = 'bfs'
node tools/restore-artwork.mjs $algorithmId
node tools/prepare-film.mjs $algorithmId
```

保留原有 `review.json`。恢复脚本逐文件核对内容；已有不同图片时会停止，不覆盖修改。`prepare-film.mjs` 将该项原教学 JSON 与影片脚本合并，并写入这台机器上存在的图片路径。公开脚本中另外指定的分镜图片采用相对路径。脚本中的 `caseFile` 还需要同目录对应反例 JSON。不要为了让检查通过手填审查状态；改变案例、漫画或讲解后，旧审查结论不能直接继承。

先只生成配音并检查自然时长，再构造画面预检，最后选择草稿或高清输出：

```powershell
media/manim/.venv/Scripts/python.exe -X utf8 media/manim/film.py media/exports/bfs.film.json media/films/bfs --narration-only
media/manim/.venv/Scripts/python.exe -X utf8 media/manim/preflight.py bfs
media/manim/.venv/Scripts/python.exe -X utf8 media/manim/film.py media/exports/bfs.film.json media/films/bfs --quality draft
# 完成草稿检查后再运行高清制作：
media/manim/.venv/Scripts/python.exe -X utf8 media/manim/film.py media/exports/bfs.film.json media/films/bfs --quality final
```

以上解释器路径适用于 Windows；其他系统使用该环境的 `.venv/bin/python`。首次配音依赖 edge-tts 网络服务；缓存齐全时复用已有逐段音频。不要把 `--technical` 用于课程绕过 90—150 秒限制。草稿与高清都会写同名 `final.mp4`，必须查看 `report.json` 的实际规格，且同一输出目录只能有一个写入进程。

如果要按修改后的算法重新计算主教学案例，先运行 `npx tsx tools/export-lessons.ts bfs`，再重新准备、制作和审查。省略 ID 会导出全部案例；这会覆盖原冻结数据。固定种子只约束计算，不保证不同字体、编码器或在线语音服务生成逐字节相同的 MP4。完整制作契约见 `media/manim/README.md`。
